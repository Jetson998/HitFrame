# HitFrame 部署指南（种子客户交付）

面向要把 HitFrame 部署给种子客户的场景。开发自测请看根 `README.md` 的「快速开始」；本文档补的是**生产/交付视角**：环境变量逐项说明、切换到客户自己的对象存储、密钥与令牌管理、以及部署后的租户初始化。

## 架构口径：一次部署 = 一个租户

HitFrame 当前按**单租户**架构交付（`M1/M2a` 既定口径）：`API_TOKEN` 是整个部署共享的唯一访问令牌，不做按 token 的租户路由。

**每个种子客户各自独立部署**：各自一份 `.env`、各自一个数据库、各自一个 `API_TOKEN`。不要把多个客户跑在同一套部署里共享余额/资产库。

## 一、部署步骤

```bash
git clone <repo> && cd HitFrame
npm install
cp .env.example .env
```

编辑 `.env`（见下方逐项说明），然后：

```bash
docker compose up -d        # PostgreSQL + Valkey + SeaweedFS（生产可跳过 seaweedfs，见下）
npm run build
npx drizzle-kit push --config apps/api/drizzle.config.ts   # 或按你们的迁移方式建表
node --env-file=.env scripts/seed.mjs                       # 写入三场景模板
node --env-file=.env scripts/init-tenant.mjs --name "<客户名称>" --points <初始点数>
```

启动服务（建议用 `pm2` / `systemd` / 容器编排常驻，而非直接前台跑）：

```bash
node --env-file=.env apps/api/dist/main.js         # API :3001
node --env-file=.env apps/api/dist/worker-main.js  # Worker（队列消费，必须与 API 分进程常驻）
```

前端 `apps/web` 构建产物（`npm run build -w @hitframe/web`）是静态文件，用 Nginx/任意静态托管即可，只需把 `/api`、`/files` 代理到 API 进程。

## 二、环境变量逐项说明

### API 基础

| 变量 | 说明 | 生产建议 |
|---|---|---|
| `PORT` | API 监听端口 | 按部署环境定 |
| `API_TOKEN` | 前端/客户端访问令牌，请求需带 `Authorization: Bearer <值>` | **必须改成随机长字符串**，不要沿用 `dev-token-change-me`。这是整个部署的唯一访问凭证，泄露等于对方可直接消耗客户点数 |
| `DATABASE_URL` | PostgreSQL 连接串 | 生产库地址，建议独立密码非默认 `hitframe/hitframe` |

### 对象存储（StorageAdapter）

| 变量 | 说明 |
|---|---|
| `STORAGE_DRIVER` | `local`=本地磁盘卷（默认/开发/回滚用）；`s3`=对象存储 |
| `STORAGE_DIR` | `local` 模式下的存储目录 |
| `PUBLIC_BASE_URL` | 本系统对外基址，`/files/{key}` 网关据此拼 URL |
| `SIGNED_URL_TTL` | `s3` 模式下签名 URL 有效期（秒），每次访问即时刷新，不用调大 |
| `S3_ENDPOINT` / `S3_REGION` / `S3_BUCKET` / `S3_ACCESS_KEY` / `S3_SECRET_KEY` | 客户 OSS 的四要素，见下节切换说明 |
| `S3_FORCE_PATH_STYLE` | SeaweedFS/MinIO 需 `true`；AWS S3 原生桶设 `false` 走 virtual-host 寻址 |

**切换到客户自己的 OSS**（阿里云 OSS / 腾讯云 COS / AWS S3 等 S3 兼容存储）：

1. 客户侧建好 bucket，拿到 endpoint / access key / secret key
2. `.env` 改：
   ```
   STORAGE_DRIVER=s3
   S3_ENDPOINT=https://oss-cn-xxx.aliyuncs.com   # 客户实际 endpoint
   S3_REGION=<客户区域>
   S3_BUCKET=<客户桶名>
   S3_ACCESS_KEY=<客户 access key>
   S3_SECRET_KEY=<客户 secret key>
   S3_FORCE_PATH_STYLE=false   # 阿里云/腾讯云/AWS 原生一般 false；SeaweedFS/MinIO 才需 true
   ```
3. 代码不用改——`StorageAdapter` 是统一接口，只吃 `.env`
4. 如果之前用 `local` 已经存了资产，用 `scripts/migrate/local-to-s3.mjs` 做存量迁移（幂等、带校验和）
5. 部署里的 `seaweedfs` 容器只是本地/演示用的 S3 兼容网关，切到客户 OSS 后可以从 `docker-compose.yml` 里去掉这个服务，不用跟着部署

### 图像引擎

| 变量 | 说明 |
|---|---|
| `IMAGE_PROVIDER` | 生产用 `muskapis`；`fake` 仅用于压测/破坏性测试，绝不能带进客户环境 |
| `IMAGE_BASE_URL` / `IMAGE_MODEL` | 供应商接口地址与模型名 |
| `IMAGE_API_KEY` | **只存服务端，永不下发前端**。生产环境务必确认这是客户/公司自己的计费 Key，不是开发测试 Key |

### 执行内核（队列）

| 变量 | 说明 |
|---|---|
| `EXECUTION_MODE` | 生产固定用 `queue`；`inline` 是 S2 前的回滚开关，交付环境不要用 |
| `REDIS_HOST` / `REDIS_PORT` | Valkey/Redis 连接（BullMQ 依赖） |
| `WORKER_CONCURRENCY` | Worker 并发数，按引擎侧限流能力调 |
| `EXECUTOR_CONCURRENCY` | 遗留于 `inline` 模式，`queue` 模式下不生效 |

## 三、密钥与令牌管理

- **`API_TOKEN`**：随机生成（如 `openssl rand -hex 32`），只通过安全渠道（非邮件明文）交给客户操作人员
- **`IMAGE_API_KEY`**：只存服务端 `.env`，前端代码/网络请求都不会看到；`.env` 不进 git（已在 `.gitignore`）
- **`S3_ACCESS_KEY`/`S3_SECRET_KEY`**：如切客户 OSS，建议客户创建一个仅限该 bucket 读写权限的子账号 Key，不要给根账号 Key
- **`DATABASE_URL`** 里的密码：生产环境改掉 compose 默认的 `hitframe/hitframe`

## 四、部署后初始化

```bash
# 1. 写入三场景模板（可重复执行，upsert 语义）
node --env-file=.env scripts/seed.mjs

# 2. 初始化客户租户点数（首次；--points 为初始点数）
node --env-file=.env scripts/init-tenant.mjs --name "客户公司名" --points 500

# 3.（如需后续追加点数，例如客户续费）
node --env-file=.env scripts/init-tenant.mjs --points 200 --topup
```

`init-tenant.mjs` 写入的是正规 `opening`/`topup` 记账流水（与 `pointsBalance == Σ 流水` 的口径一致），不是直接改数据库字段，全程可审计。

## 五、上线前检查清单

- [ ] `.env` 里 `API_TOKEN` 已改为随机值（非 `dev-token-change-me`）
- [ ] `IMAGE_PROVIDER=muskapis`（不是 `fake`）
- [ ] `IMAGE_API_KEY` 是客户/公司正式计费 Key
- [ ] `EXECUTION_MODE=queue`（不是 `inline`）
- [ ] 存储已确认：`local`（本地卷，注意备份）或已切换到客户 OSS 并验证可读写
- [ ] `docker compose up -d` 后 `postgres`/`valkey` 健康；若用客户 OSS，本地 `seaweedfs` 服务可移除
- [ ] `scripts/seed.mjs` 已跑（三模板已写入）
- [ ] `scripts/init-tenant.mjs` 已跑（租户点数已初始化，非 0）
- [ ] API + Worker 均已常驻运行（非临时前台进程，重启会打断在途任务）
- [ ] 已按「已知限制与故障处理」文档过一遍风险点
